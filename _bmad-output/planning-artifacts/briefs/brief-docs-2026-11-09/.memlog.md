- (event) Create intent. User supplied an initial brief (saved to inputs/initial-brief.md): standardize docs/READMEs across all Hexalith modules per GitHub OSS best practices; principles = written for people, concise top level with details in linked sub-docs, self-sufficient README; README links artifacts (NuGet) and quality indicators (Coverity, SonarQube, others).
- (event) Observed: 21 module repos under github.com/Hexalith (plus xppmodel under Itaneo); README lengths range from 0 to 1275 lines; several repos have no or near-empty README. Survey + web research subagents launched.
- (event) Survey done: only ~5 of 20 READMEs are presentable (best: eventstore, tenants); READMEs serve 3 conflicting roles (product intro / contributor runbook / release-evidence log).
- (event) Survey: builds/Hexalith.Package.props packs the root README into every NuGet package, so README quality = nuget.org package page quality (e.g. Hexalith.Projects.Contracts shows only a title).
- (event) Survey: internal BMAD planning content (epics, stories, FR/NFR ids, _bmad-output links, backlogs) leaks into READMEs/CONTRIBUTING/docs; most docs are AI-agent written; aitools shared agent instructions carry no README rules.
- (event) Survey: no Hexalith/.github org repo; no SECURITY/SUPPORT/issue/PR templates anywhere; Coverity/Sonar/Codacy badges exist in 2 repos but no CI workflow produces those metrics; several broken badge/links.
- (event) Survey: builds repo is the de facto enforcement layer (reusable workflows used by 16 repos, Package.props); eventstore has unused markdownlint/lychee configs and a page template.
- (event) Side finding flagged to user: bmadskills tracks 106 .claude.json files under skills/reports/ that may hold sensitive content; out of brief scope.
- (event) Research: a public Hexalith/.github repo can supply org-wide defaults (CONTRIBUTING, CoC, SECURITY, SUPPORT, issue/PR templates) but not LICENSE; template repos copy once with no sync.
- (event) Research: nuget.org renders README via Markdig, no raw HTML, no relative links/images, image allow-list (shields, sonarcloud, codecov, GH workflow badges yes; scan.coverity.com, scorecard, bestpractices no) - one README for GitHub+NuGet is a real design decision.
- (event) Research: SonarQube Cloud (ex-SonarCloud) has a free OSS plan since 2026-01-27; Coverity Scan (Black Duck) still free for OSS incl. C# but has outages and an unclear EOL note - fragile; OpenSSF Scorecard and Best Practices (new Baseline series) are free.
- (event) Research: org rulesets/required workflows need GitHub Team/Enterprise (plan unknown); reusable workflows (already used via builds) + markdownlint-cli2, Vale (added-lines mode), lychee are the realistic enforcement path.
